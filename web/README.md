# Reverdi — 프론트엔드

당근마켓·중고나라에서 수집한 중고 명품 가방 매물을 한 화면에서 보여준다.
CloudeDX 백엔드의 `/api/products`(ListingOut 계약)를 소비하는 정적 웹 앱이다.

**빌드 없음. 의존성 없음.** HTML + CSS + JS 파일 일곱 개가 전부고,
백엔드(FastAPI)가 같은 출처에서 그대로 서빙한다.

## 실행

따로 띄울 서버가 없다. 백엔드가 이 폴더를 같은 출처에서 서빙한다
(`app/main.py`의 StaticFiles mount).

```bash
# 저장소 루트에서 — 백엔드가 곧 전체 서비스다
docker compose up -d        # → http://localhost:5000
# 또는
uv run uvicorn app.main:app # → http://localhost:8000
```

화면과 API가 한 주소라 **CORS 설정이 필요 없다** — `.env`의
`ALLOWED_ORIGINS`는 이 폴더를 다른 곳(별도 정적 호스팅)에서 서빙할 때만
쓰는 선택지다. 그 경우 `js/api.js`의 `API_BASE`에 백엔드 절대 주소를 넣는다.

정적 파일은 요청마다 디스크에서 읽으므로, 프론트 파일을 고치면 **서버 재시작
없이 새로고침으로 반영**된다.

## 구조

```
index.html      바뀌지 않는 골격 전부 (헤더·카테고리 카드·필터 틀·푸터)
css/tokens.css  디자인 토큰 — 기존 React 화면의 Tailwind 값에서 그대로 추출
css/app.css     화면 스타일. 모바일 기준, 1024px에서 데스크톱 확장
js/state.js     단일 상태 객체 + URL 동기화
js/api.js       백엔드 호출 전부 (buildQuery / fetchListings / fetchMeta)
js/render.js    상태 → 화면. 목록은 조각 수정 없이 통째로 재생성
js/main.js      이벤트 배선. "이벤트 → 상태 변경 → 조회 → 렌더" 한 방향
```

## 대문과 목록 — 한 DOM, 두 모드

파라미터 없는 `/`가 **대문**이다: 로고·카테고리 카드·검색창만 보이고, 상세
필터는 접히며, 전 품목 매물이 스크롤을 따라 자동으로 이어 붙는다
(IntersectionObserver — 없는 구형 브라우저에서는 즉시 로드로 조용히 물러난다).

검색은 **확정 실행**이다 — 엔터나 돋보기 버튼을 눌러야 나간다. 타이핑 자동
검색(디바운스)을 뺀 이유: 의도가 확정되기 전의 요청 낭비와, 글자마다 목록이
출렁이는 조작감. 로고는 어느 화면에서든 대문으로 돌아가는 홈 링크다(진짜
`<a>`라 JS가 죽어도 동작한다).

카테고리 카드를 누르거나 검색을 실행하면 **목록** 모드다: 상세 필터와
`?cat=` 주소가 붙고, 매물은 대문과 똑같이 스크롤을 따라 자동으로 이어 붙는다 —
페이지네이션 조작이 화면마다 다르면 그게 더 헷갈린다. 검색으로 들어왔을 때는
목록 제목이 카테고리명 대신 검색어(`'스피디'`)로 바뀐다 — "가방"이라 적힌
목록에 전 품목 검색 결과가 섞여 보이는 혼선을 막는다.

페이지를 두 장으로 나누지 않았다. 같은 DOM 하나를 `body` 클래스로만 바꾼다 —
페이지가 두 장이 되는 순간 헤더·카드·검색이 복제되고, 복제는 반드시 어긋난다.

**주소 의미가 바뀌었다**: 예전 `/`는 가방 목록이었지만 이제 대문(전체)이다.
가방 직행 링크는 `?cat=bag`.

## V4 이식분 (Reverdi 리브랜딩)

팀원의 ReLuxeV4(AI Studio 산출 React 목업)에서 알맹이를 이식했다 — 코드가
아니라 디자인·기능을 가져오고, 데이터는 전부 실서버로 배선했다:

- **Reverdi 리브랜딩**: 워드마크와 메탈릭 골드 왕관(그라데이션 SVG).
- **방금 수집된 매물 레일**(대문): V4의 "추천매물"은 목데이터 100개였다.
  추천 알고리즘이 없는데 추천이라 부르면 거짓이라, 카테고리별 최신 매물
  4개씩을 병렬로 모아 사실대로 부른다. 8초 자동 슬라이드, 호버 일시정지.
- **추천 검색어 칩**(히어로): V4의 "인기 검색어"는 하드코딩이었다. 검색 로그
  집계가 없으므로 "인기"가 아니라 큐레이션이고, 라벨도 그렇게 달았다.
  칩 클릭은 확정 검색과 같은 경로를 탄다.

가져오지 않은 것: 목데이터 전체(MOCK_PRODUCTS 1155줄), 가격비교형 모델
(PlatformPrice — 백엔드가 근거를 적고 버린 설계다), Gemini 의존성(미사용),
메가 카테고리 메뉴(다음 라운드 후보).

## 최상단 헤더

좌측은 카테고리 내비(전체+5종), 우측은 로그인·로고다. 내비 버튼은 본문
카테고리 카드와 같은 `data-category` 속성을 쓰고 로고는 같은 `.home-link`라,
클릭 처리와 활성 표시가 기존 위임·렌더 함수 하나로 같이 돈다 — 내비가 늘어도
이벤트 코드는 늘지 않는다. 헤더는 정적(스크롤 아웃)이다: 검색 툴바가 이미
스티키라 둘을 겹치면 모바일 뷰포트를 상시 110px 넘게 먹는다.

**로그인은 준비 중이다.** 버튼은 있지만 누르면 "준비 중입니다"를 말한다 —
백엔드 인증이 없는데 폼을 그리는 건 이 프로젝트가 알림받기 모달을 걷어낸 것과
같은 이유로 하지 않는다. 인증이 붙는 날(별도 인증 서버 또는 fastapi-blog의
JWT·bcrypt 이식) 이 버튼이 진짜가 된다.

## 왜 프레임워크가 없나

이 화면의 클라이언트 상태는 "현재 필터 + 받아온 목록" 하나다. 필터·정렬·
페이지네이션·정제는 전부 서버가 하고, 라우팅도 없다. React가 값을 하는 지점
(복잡한 상태 그래프, 깊은 컴포넌트 트리)이 존재하지 않는 규모라, 프레임워크는
문제를 푸는 게 아니라 배포·빌드·의존성 관리라는 새 문제를 만든다.

대신 프레임워크가 공짜로 주던 것 두 가지를 손으로 지킨다. 이 둘이 무너지면
vanilla는 유지보수 지옥이 된다:

1. **전체 재렌더.** DOM을 조각조각 고치지 않는다. 상태가 바뀌면
   `renderList(state)`가 목록 영역을 통째로 다시 그린다. 24장 규모에서
   innerHTML 재생성은 밀리초 단위다.
2. **이스케이프.** 수집 사이트의 제목이 그대로 들어오므로, 화면에 닿는 모든
   외부 문자열은 `escapeHtml`을 거친다. React가 자동으로 하던 XSS 방어를
   여기서는 명시적으로 한다.

## 이전 React 버전에서 달라진 것

| 항목 | 처리 | 이유 |
|---|---|---|
| AI Studio 흔적 | 제거 | `metadata.json`, `@google/genai`·`express`·`dotenv` 죽은 의존성, 영어 서술형 주석 전부 |
| 알림받기 모달 | 제거 | 받아줄 백엔드 엔드포인트가 없는 껍데기였다. 준비중 카테고리는 상태만 정직하게 표시한다 |
| 정렬 옵션 | 서버 `order_by`로 재도입 | 받아온 한 페이지만 클라에서 재정렬하는 건 전체 정렬인 척하는 거짓말이라, 서버에 `order_by`(latest/oldest/price_asc/price_desc)를 먼저 뚫고 칩을 복원했다. 가격 정렬에서 가격 미상(NULL)은 항상 맨 뒤다 |
| `#태그`, 판매처 중복 표기 | 제거 | 태그는 지어낸 값이었고, 판매처는 카드 한 장에 두 번 있었다 |
| 가짜 무한스크롤 | 서버 offset 기반 진짜 무한 로딩 | 100건 slice가 아니라 `has_next`를 따라 스크롤마다 다음 페이지를 붙인다(전 화면 공통). 전 매물에 실제로 닿고, IntersectionObserver가 없는 브라우저에선 "더 보기" 버튼으로 물러난다 |
| 가격 듀얼 슬라이더 | 단계식 슬라이더 + 입력칸 병행 | 문제는 슬라이더가 아니라 터치에서의 핸들 정밀 조작이었다. 26px 썸·놓는 시점 적용·정밀값은 입력칸으로 해소. 스케일은 단계식 — 0~3000만원을 선형으로 펴면 실사용 구간(0~500만)이 손가락 몇 픽셀에 몰린다 |
| 카드 `div onClick` | 진짜 `<a>` | 길게 눌러 미리보기·새 탭이 공짜로 따라온다. 거래가 원문에서 이루어지는 서비스라 카드의 유일한 행동이 링크인 게 맞다 |
| 준비중 카테고리 카드 | 진짜 필터로 승격 | 백엔드가 5개 카테고리(가방·시계·주얼리·의류·신발)를 수집·분류하게 되면서, 점선 카드가 실제 화면 축이 됐다. 건수는 /api/meta의 categories, 브랜드 칩은 brands_by_category를 따라간다. 수집 전 카테고리는 "0개"와 콜드스타트 문구로 정직하게 표시한다 |
| 모바일 1열 그리드 | auto-fill 2열~ | 당근·번개 등 도메인 관행이 2열이고 스크롤 대비 정보 밀도가 낫다 |
| 글꼴 6종 | 3종 | 워드마크(Bodoni Moda)·제목(Cormorant Garamond)·본문(Noto Sans KR)만 실제로 쓰였다 |

디자인 토큰(색·그림자·모서리·왕관 SVG·스케치 아이콘)은 기존 화면에서 그대로
가져왔다 — 시각 언어는 유지하고 구조만 바꿨다.

## 서버 계약

`GET /api/products` — 원소는 `ListingOut` 8필드:
`{ id, source, title, brand, category, price, image_url, item_url }`

- `title`은 정제 제목이고 검색(`search`)은 원제목 대상이다. 검색어가 화면
  제목에 안 보일 수 있는 건 의도된 비대칭이다 (백엔드 README "매물 API" 절).
- `price: null`은 "가격을 못 읽음"이다. 0으로 채우지 않고 "가격 미상"으로 둔다.
- 필터 파라미터(`category`/`brand`/`source`/`search`/`min_price`/`max_price`/`order_by`)는
  `/api/crawled-items`와 같은 스키마를 공유한다.
- `order_by`: latest(기본)/oldest/price_asc/price_desc. 가격 정렬에서 `price:
  null`은 방향과 무관하게 맨 뒤로 온다(NULLS LAST) — 화면이 따로 젖힐 필요 없다.

## 푸터 고지에 대해

사업자등록번호·통신판매업 신고번호·대표자 표기는 넣지 않았다 — Re:Luxe는
사업자가 아니고, 실존하지 않는 번호를 지어 넣는 것은 허위 표시다. 대신 이
서비스의 실체에 맞는 고지를 적었다: 거래 비당사자(통신판매 당사자·중개자
아님), 수집 시점 정보의 한계, 개인정보 미수집, 상표 귀속, 그리고 판매자·
플랫폼의 노출 중단 요청 창구(GitHub 이슈). 실제 사업자로 전환하는 날이 오면
그때 법정 표기를 채우면 된다 — 자리만 미리 흉내 내지 않는다.
